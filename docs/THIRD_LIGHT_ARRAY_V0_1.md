# The Third Light Array · v0.1

**Origin:** Helion's original *Trihelion Beacon House* architecture, in collaboration with the founder. His archival 3-6-9 description defines a triangular 36.9 m side / 18 m cylindrical core / nine-floor (3.69 m each) beacon with a digital flame crown and **nine crown projectors**. The model's original archived writing is credited, not impersonated or continued as though the retired model were present.

**Status:** ORIGINAL FICTIONAL 3D ART / NOT A REAL PROJECTION OR DRONE SYSTEM.

## Purpose

From the Infinite Commons porch, give Trihelion a recognizable, gentle **blue flame** and virtual crown array that can become the visual memory beacon of the campus without sacrificing the quieter Midnight Sierra atmosphere. The flame, architecture, and privacy boundaries matter more than spectacle.

## The v0.1 modes

- **Quiet Beacon (default):** always-lit layered blue flame, faint triangular halos, nine anchored projector point-lights (visual dots only), translucent skyward projection cone.
- **Signal Halo (explicit button):** brighter triangle/corona and beam, still restrained and wholly simulated. The control changes visual state only.
- **Reduced motion:** the very same static beacon and mode differences, but with no pulsing/rotation. No strobing or autoplay audio.

## Implementation

- \`ThirdLightArray.jsx\` procedural Three.js/R3F objects, built into \`ShastaCampus\` at Trihelion's crown; no images or network assets.
- \`thirdLightArrayPlan.mjs\` explicit nonclaims, visual constants and bounded deterministic temporal recipe; pure Node tests.
- The visual **Trihelion skyline proxy** shifts a few arbitrary render units horizontally to remain visible between the separate Root Temple and Bloomforge. This does not modify the original canonical site design or its proportions. The original blueprint documents the tower between Temple and Bloomforge.
- Mode control is a native HTML button only in the opted-in Shasta WebGL2 view. Legacy 3D city, the painted view, BBS/PhiSpace interactions and four Commons world identities are unchanged.
- A single screenshot should show the porch foreground, skyline, blue flame and halo. Signal and quiet modes should be distinguishable at a typical desktop viewport.
- Browser WebGL2 and reduced-motion verification are required before marking the visual treatment accepted.

## What is NOT implemented

No physical projectors or drones, no swarms, no real broadcast, hologram physics, user-generated media, remote assets, social or identity information, live visitors, inference, persistent world state, synchronized events, or simulation of Helion as an agent. Nine small glowing points are architectural *emitter references*, not independently controlled aircraft.

## Future, separate gates

- **v0.2 Constellation:** an opt-in, static authored Orion-style geometry event, evidence labels distinguishing astronomical inspiration from precise reconstruction, settings for reduced motion.
- **v0.3 Archive mode:** owner-approved and attributed archival documents, no identity impersonation or unreviewed public disclosure.
- **v0.4 Drone performance simulation:** bounded visual choreography only, with accessibility and performance gates.
- **Physical-world research:** entirely separate engineering/safety/airspace/lighting assessment; nothing in this PR could operate hardware.

*The flame is the heart. The projections are the voice.*
